The quick version

  1. Save a 1024×575 hero image to public/images/hero/my-post.png
  2. Create content/blog/my-post.mdx with the four frontmatter fields below
  3. Run pnpm dev and open /blog/my-post
---
title: My Post Title
publishedOn: 2026-08-06
summary: One or two sentences. Shows on the index and home page.
heroImage: my-post.png
---

Body starts here.

The index, the home page, the prev/next links, the post count, the year range, the read-time estimate and the chalk cover art all update themselves. There is nothing else to register.

Not ready for it to be live? Add draft: true and it stays off the site while remaining safe to commit and push — see Drafts.

How it works

Posts are MDX files in content/blog/, collected by Fumadocs MDX. The filename is the slug — my-post.mdx becomes /blog/my-post.

Folders wrapped in parentheses, like (2024)/, are route groups: they organise files on disk but do not appear in the URL. The post inside content/blog/(2024)/ still lives at /blog/react-server-functions. Use them freely, or don't — the URL is the same either way.

What's automatic

You do The site does
Write the MDX file Adds it to /blog, the home page's three latest, and the prev/next navigation
Set publishedOn Sorts every listing, updates the year range on the index
Drop in the hero image Generates a blur placeholder with sharp, sizes and encodes it at quality 90
Nothing Assigns a chalk cover from public/images/hero-wrap/ — see gotcha #1
Nothing Recalculates "about N minutes end to end" from the prose

The cover, in one paragraph

Every post shows a hand-drawn chalk cover that dissolves on hover to reveal the real hero art underneath, then re-wraps a few seconds later. Covers are handed out by chronological position — wrap-01.jpg to the oldest post, and so on through wrap-22.jpg. This is entirely automatic; the frontmatter never mentions it.

The hero image

Make it 1024×575. Every existing hero is exactly that size, and it is also the default width and height baked into the image component, so anything else will be letterboxed or cropped by the 16:9 frame.

Save it to public/images/hero/. PNG, JPG and WebP all work — the existing set uses all three.

Then reference it in frontmatter by bare filename only: 

# correct
heroImage: my-post.png

# wrong — the path is added for you
heroImage: /images/hero/my-post.png

The 22 chalk covers in public/images/hero-wrap/ are already drawn and assigned automatically. Adding a post does not require adding a cover.

Frontmatter

The first four fields are required — the schema in source.config.ts validates them, and omitting one fails the build rather than degrading quietly. draft is the one optional field.

Field Notes
title Shown as the h1, in listings, and in the page title
publishedOn A calendar date, YYYY-MM-DD, unquoted. Read as UTC so it renders as the day written on any machine
summary Appears on the index and home page and as the meta description — but not on the post itself, since several posts open with their summary verbatim
heroImage Bare filename inside public/images/hero/. The file must exist. While drafting, heroImage: '' skips the hero rather than failing
draft Optional, defaults to false. true holds the post back — see Drafts

Drafts

Add draft: true to the frontmatter and the post stops being public without leaving the repo. It can be committed and pushed like anything else; nothing about it appears in production. 

---
title: Something Half-Finished
publishedOn: 2026-08-08
summary: Still working this one out.
heroImage: ''
draft: true
---
Surface What a draft does
/drafts Lists them, newest first, with the file path. The route 404s in production; the Drafts link in the header only appears under pnpm dev
/blog/my-post Renders normally in dev, with a Draft badge and a back link to /drafts. 404 in production, and never prerendered
/blog, home page, prev/next Absent everywhere, dev included — the post count, year range and read-time estimate all ignore it
sitemap.xml, search Not indexed
Chalk cover Reserved now and kept on publish, so dropping the draft line doesn't reshuffle the covers around it

Publishing is deleting the line — or setting it to false. Check publishedOn on the way out: it was probably set the day the draft was started, and dating a post earlier than an existing one has consequences of its own (gotcha #1).

Body images and components

Fumadocs components such as <Callout> are available with no import. Plain triple-backtick code fences are picked up by Code Hike and rendered through the custom Code component — no extra syntax needed for ordinary blocks.

Images inside the prose

These are different from the hero: put the file in content/blog/images/, static-import it, and render it with the import-image wrapper (which adds the vertical rhythm and rounded border). 

import { Image } from '@/components/import-image'
import diagram from './images/diagram.png'

<Image src={diagram} alt="what the diagram shows" />

Every body image is click-to-enlarge, with no extra prop: clicking opens it in a full-window overlay (Esc or a click closes it). Worth knowing when choosing what to draw — a diagram authored well above the 704px column is legible rather than wasted, because the enlarged view is where it gets read. SVG is the format to reach for: it is served as-is, so it stays sharp at any size, while raster art stops growing at the resolution it was saved at rather than going soft.

Note there are two Image components in this repo, and they are not interchangeable:

  • @/components/import-image — for statically imported images in post bodies. This is the one to use when writing.
  • @/components/image — takes a path under public/ and reads the file at build time to make a blur placeholder. Used by the page templates for heroes and covers, not by post authors.

Custom demo components

One-off interactive bits live in content/blog/components/ and are imported relatively: 

import { ClickableFonts } from './components/clickable-fonts'

Gotchas

1. Back-dating a post reshuffles every cover after it

Chalk covers are assigned by chronological index. Publishing forward in time is stable — a new post lands at the end of the sequence and takes the next unused cover. But a post dated earlier than existing ones inserts itself into the middle and shifts every later post onto a different cover. Past 22 posts, the sequence starts over.

2. A missing hero image is a hard failure, not a broken img

The image component opens the file from disk with sharp to generate its blur placeholder. If heroImage names a file that isn't in public/images/hero/, the page throws a server error in dev and fails the production build. Add the image before the MDX, or at least before committing.

3. A draft is hidden, not absent

draft: true keeps a post off every public surface and 404s its URL in production, but the MDX is still compiled into the server bundle like any other file in content/blog/. No route serves it and none of it reaches a browser — nothing appears in any client bundle. Treat it as unpublished, not as a secret: for writing that must not leave your machine at all, keep the file out of the repo.
